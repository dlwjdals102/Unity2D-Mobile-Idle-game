# 검은탑 키우기 (가제) — 게임 기획 & 기술 설계서

> 포트폴리오 목적: **클라이언트 프로그래밍(구조 설계 · 최적화) 역량 증명**
> 개발 기간: 18주 / 1인 개발
> 환경: Unity 6000.3.9f1, URP 2D, Input System, 세로 모드 모바일

> **개정 이력**
> - v2 (W6 시점): 단일 캐릭터 → **3인 파티**로 전환. 몬스터가 반격하고 아군이 죽는다.
>   이에 따라 체력·방어력이 실제 의미를 갖게 되었고, 일정이 12주 → 18주로 늘었다.
>   전환 근거는 `Docs/Architecture.md`가 아니라 이 문서 §3에 기록한다.

## 1. 컨셉

**한 줄 피치**
> 전사·궁수·마법사 3인 파티가 끝없는 탑을 자동으로 올라가는 방치형 RPG.

| 항목 | 내용 |
|------|------|
| 장르 | 2D 방치형 파티 RPG (판타지) |
| 플랫폼 | Android (세로 모드, 1080x1920 기준) |
| 아트 톤 | 도트 or 미니멀 실루엣 — 통일된 팔레트 우선, 물량 최소화 |
| 세션 설계 | 1일 3~5회 접속 × 회당 2~4분 |

### 스코프 원칙 (1인 개발에서 이 장르가 무너지는 지점)

> **구조는 야심차게, 콘텐츠는 최소로.**

캐릭터는 슬롯당 3종(총 9종), 장비는 15종으로 **고정**한다.
9슬롯 장비와 파티 전투가 "돌아간다"는 걸 보여주는 데 이 이상은 필요 없고,
종수를 늘리는 것은 아트 리소스가 확보된 뒤 **데이터만 추가하면 되는 일**이다.
평가자에게 보이는 것은 종수가 아니라 구조다.

## 2. 코어 루프

```
[접속]
  └─ 오프라인 보상 수령 (+광고 2배)
       └─ 골드 소비 → 캐릭터별 스탯 강화
            └─ 층 돌파 → 보스 → 다이아
                 └─ 가챠 (캐릭터 / 장비)
                      └─ 편성·장착 조정
                           └─ 자동 전투 켜두고 이탈
                                └─ (반복) ─ 벽이 두꺼워지면 → [환생]
```

### 스테이지 구조
- 탑의 **층(Floor)** 단위. 1층부터 무한
- 일반 층: 몬스터 10마리 처치 → 다음 층
- **10층마다 보스**: 제한시간 30초
- 돌파한 최고 층까지는 자유 이동 가능 (파밍용)

## 3. 전투 규칙 (확정)

### 파티

전사 · 궁수 · 마법사 **3슬롯 고정**. 슬롯마다 캐릭터 1명을 배치한다.

| 직업 | 성향 | 공격 주기 |
|---|---|---|
| 전사 | 체력·방어 높음, 공격력 낮음 | 1.0초 |
| 궁수 | 균형 | 0.6초 |
| 마법사 | 공격력 높음, 체력·방어 낮음 | 1.4초 |

**공격 주기는 직업별 고정 상수이며 스탯이 아니다.**
강화나 장비로 변하지 않는다. 공격 속도를 성장 가능한 스탯으로 만들면 공격력과 곱으로 작용해
DPS가 제곱으로 뛰고, 그 시점부터 밸런싱이 사실상 불가능해진다.

### 진행

- 몬스터는 **한 번에 한 마리**. 아군 3인이 동시에 그 한 마리를 때린다
- 몬스터는 **슬롯 순서(전사→궁수→마법사)상 살아 있는 첫 아군**을 때린다
  - 어그로·도발·전열/후열 판정은 없다. 슬롯 순서가 곧 맞는 순서다
  - 전사가 앞에 있는 것이 "탱커"의 의미 전부다

### 데미지

```
최종 데미지 = 공격력 × 방어상수 / (방어상수 + 방어력)
              × (치명타면 치명타 배율)
```

- **비율 감소형**을 쓴다. 감산형(`공격력 - 방어력`)은 방어력이 공격력을 넘는 순간
  데미지가 0이 되어 무한 성장 게임에서 곧바로 깨진다
- **방어상수는 임시로 100**을 쓴다. 방어력 스케일이 확정된 뒤,
  해당 범위 중간값에서 감소율이 약 50%가 되도록 역산해 확정한다 **(추후 조정)**
- 회피는 초기 버전에서 **제외**한다. 판정이 하나 늘어나는 만큼 밸런싱 축이 늘어나고,
  방어력만으로도 생존 곡선은 충분히 만들어진다

### 사망과 실패

- 체력이 0이 된 아군은 **그 층이 끝날 때까지 부활하지 않는다**
- **층이 바뀌면 전원 부활 + 완전 회복.** 전투 중 회복은 없다
  - 그래야 "한 층 10마리를 버틸 수 있는가"가 생존 체크로 작동한다
- **전멸하면 그 층을 처음부터 다시 시작한다. 층은 잃지 않는다**
  - 방치형에서 진행도 손실 페널티는 이탈로 직결된다. 시간만 잃게 한다
- **보스 층은 실패 조건이 둘**이다: 제한시간 초과, 그리고 전멸

## 4. 캐릭터

- 슬롯당 **3종**, 총 9종. 등급이 곧 성능 (Common / Rare / Epic)
- 시작 시 각 슬롯의 Common 1종을 보유·장착한 상태로 출발한다 (전투가 성립해야 하므로)
- 나머지는 **다이아 가챠**로 획득
- **중복 획득 시 해당 캐릭터의 각성 단계 +1** (스탯 배율 상승)
  - 별도의 조각 재화를 만들지 않기 위한 처리다

## 5. 성장 축

| 축 | 재화 | 단위 | 비고 |
|---|---|---|---|
| 스탯 강화 | 골드 | **캐릭터별** | 공격력 / 체력. 무한 단계 |
| 장비 | 다이아(가챠) | **캐릭터별 3슬롯** | 3캐릭터 × 3슬롯 = 9슬롯 |
| 각성 | 중복 캐릭터 | 캐릭터별 | 가챠 중복의 처리처 |
| 환생 | — | 전체 | 영구 배율 (골드 획득량 포함) |

### 장비 슬롯

| 슬롯 | 기여 |
|---|---|
| 무기 | 공격력 배율 |
| 방어구 | 체력 배율 + 방어력 |
| 장신구 | 치명타 확률 가산 (상한 75%) |

> **방어구가 v2에서 부활했다.** v1에서는 플레이어가 피격당하지 않아 방어 스탯이
> 아무 일도 하지 않았기 때문에 제외했다. 파티 전투가 들어오면서 의미가 생겼다.
> 골드 획득량은 장비에서 빼고 환생 축으로 옮긴다 — 캐릭터별 슬롯에 두면
> 3명이 각각 착용해 배율이 겹치는 이상한 구조가 된다.

## 7. 클라이언트 아키텍처 (포트폴리오 핵심)

### 7.1 어셈블리 레이어 (실제 구성)

```
Game.Presentation   MonoBehaviour · UI          UnityEngine 사용
      ↓
Game.Gameplay       전투 · 성장 · 장비          noEngineReferences
      ↓
Game.Core           BigNumber · 풀 · 세이브     noEngineReferences
```

아래 두 계층은 `UnityEngine`을 쓸 수 없다. 이 제약 덕분에 게임 로직 전체가
씬도 PlayMode도 없이 EditMode 테스트로 검증된다. 자세한 것은 `Docs/AssemblyDefinitions.md`.

### 7.2 직접 구현하는 것 (= 어필 포인트)

| 항목 | 상태 |
|---|---|
| **BigNumber** — 가수 + 무제한 지수, 연산자 오버로딩, 단위 표기 | 완료 |
| **ObjectPool\<T\>** — 이중 반납 감지 | 완료 |
| **SaveStore** — 원자적 쓰기, 체크섬, 마이그레이션 체인 | 완료 |
| **StatComposer** — 여러 기여자를 합쳐 전투 스탯을 만드는 단일 작성자 | 파티용 재구성 |
| **데이터 파이프라인** — CSV → ScriptableObject 에디터 툴 | W9 |
| **TickManager** — 매 프레임 갱신 대상이 많아질 때 | 미정 |
| **EventBus** — 서로 참조 없는 시스템이 3개 이상 얽힐 때 | 미정 |

마지막 두 개는 **호출자가 생기면** 만든다. 지금 만들면 API를 추측으로 짜고 나중에 갈아엎게 된다.
현재 무엇이 왜 없는지는 `Docs/Architecture.md` §7에 정리되어 있다.

## 8. 밸런싱 수식 (1차안)

| 대상 | 수식 |
|---|---|
| 몬스터 체력 | `HP(n) = 10 × 1.16⁽ⁿ⁻¹⁾` (n = 층, 1-based) |
| 몬스터 공격력 | `ATK(n) = 2 × 1.15⁽ⁿ⁻¹⁾` **(추후 조정)** |
| 골드 드랍 | `Gold(n) = 5 × 1.14⁽ⁿ⁻¹⁾` |
| 보스 체력 | 동일 층 일반 몬스터 × 12 |
| 스탯 강화 효과 | `Value(k) = base × 1.075ᵏ` |
| 강화 비용 | `Cost(k) = base × 1.095ᵏ` |
| 방어 감소 | `× 100 / (100 + 방어력)` **(추후 조정: 상수 역산)** |
| 오프라인 수익 | `초당 골드 × min(경과초, 28800) × 0.6` |

**핵심 원칙**: `costGrowth(1.095) > valueGrowth(1.075)` → 단계가 오를수록 필연적으로 정체 →
다른 성장 축으로 유도. 이 관계는 테스트로 고정되어 있다.

**몬스터 공격력 곡선이 체력 곡선보다 느리게(1.15 < 1.16) 잡힌 것은 의도적이다.**
둘이 같은 속도로 자라면 방어력 비율 감소와 맞물려 실효 난이도가 층당 배율의 제곱으로 오른다.

**검증 방법**: 헤들리스 밸런싱 시뮬레이터로 "n시간 플레이 시 도달 층"과
"처음 막히는 층"을 출력한다. W14에서 만든다.
